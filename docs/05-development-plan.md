# WorkEnglish Coach 开发计划

## 1. 开发原则

1. 每个阶段结束后都必须可以运行。
2. 优先实现闭环，不优先实现大量页面。
3. 先支持本地使用，再考虑发布。
4. 所有功能都要有最小可测试版本。
5. AI 输出必须结构化校验。
6. 不允许把所有逻辑写在 React 组件里。
7. 不允许跳过错误处理。
8. 不允许为了"以后扩展"提前引入复杂架构。

---

## 2. 阶段 0：项目初始化

目标：

- 创建 Electron + React + TypeScript 项目。
- 配置 Vite。
- 配置 ESLint、Prettier、Vitest。
- 配置 Electron 安全选项。
- 实现 Main、Preload、Renderer 基础通信。
- 创建基础路由和布局。

验收：

- `npm run dev` 可以启动。
- Electron 窗口正常显示。
- Renderer 可以通过 preload 调用一个测试 IPC。
- Renderer 无法直接访问 Node.js。
- TypeScript strict 模式通过。

---

## 3. 阶段 1：基础界面

实现页面：

- 工作台。
- 今日训练。
- 表达库。
- 设置。

实现：

- 左侧导航。
- 页面路由。
- 空状态。
- 加载状态。
- 错误状态。
- 基础 Ant Design 组件。

验收：

- 页面可以正常切换。
- 刷新或重新打开应用后窗口正常。
- 没有明显控制台错误。

---

## 4. 阶段 2：SQLite 和数据层

实现：

- SQLite 初始化。
- Drizzle schema。
- 数据库迁移。
- Repository 层。
- Settings Service。
- 表达库 CRUD。
- 错误档案查询。
- 数据导出。

验收：

- 应用首次运行自动创建数据库。
- 可以新增、编辑、删除表达。
- 重启应用后数据仍存在。
- 导出 JSON 文件成功。
- 删除全部数据需要二次确认。

---

## 5. 阶段 3：AI 配置

实现：

- 设置 Base URL。
- 设置 Model。
- API Key 保存到 Windows Credential Manager。
- 测试连接。
- 超时设置。
- AI 错误提示。
- 请求耗时记录。

验收：

- API Key 不显示在日志中。
- API Key 不进入 Renderer。
- API Key 不保存到普通 SQLite 字段。
- 错误 API URL 能显示可理解提示。
- 超时不会导致应用卡死。

---

## 6. 阶段 4：工作台纠错

实现：

- 输入表单。
- 场景、对象、语气选择。
- 调用 AI。
- 输出结构化结果。
- 最小修改版。
- 自然表达版。
- 错误列表。
- 重点知识点。
- 练习题。
- 一键复制。
- 保存知识点。
- 保存样本。

验收：

- 正常英文可以得到结果。
- 语法错误可以得到解释。
- AI 返回非法 JSON 时应用可以处理。
- AI 请求失败可以重试。
- 用户可以选择不保存原文。
- 修改结果不能丢失日期、数字和责任人。

---

## 7. 阶段 5：今日训练和复习

实现：

- 根据 skills 和 expressions 生成任务。
- 任务列表。
- 提示按钮。
- 查看参考答案。
- 提交答案。
- AI 评价答案。
- 保存 attempt。
- 计算 nextReviewAt。
- 显示复习完成状态。

验收：

- 保存一个知识点后可以生成复习任务。
- 用户提交答案后可以看到反馈。
- 使用提示和不使用提示被区分记录。
- 复习任务可以按照 scheduledAt 查询。
- 重启应用后任务状态不丢失。

---

## 8. 阶段 6：统计和错误档案

实现：

- 本周练习次数。
- 独立完成次数。
- 高频错误。
- 待复习数量。
- 近七天趋势。
- 错误详情页面。

注意：

- 不展示没有意义的综合英语分数。
- 不把 AI 润色次数算作学习次数。
- 重点展示"独立输出能力"。

---

## 9. 阶段 7：口语基础能力

实现：

- 录音按钮。
- 录音计时。
- 保存临时音频。
- 语音转文字。
- 口语内容分析。
- 重新录音。
- 删除音频。

第一版口语分析只判断：

- 信息完整性。
- 语法。
- 词汇。
- 表达清晰度。
- 是否包含下一步行动。

暂不实现：

- 发音精确评分。
- 实时打断。
- 虚拟人物。
- 复杂语音情绪识别。

---

## 10. 阶段 8：桌面体验优化

实现：

- 全局快捷键打开应用。
- 快速粘贴当前剪贴板文本。
- 窗口置顶，可选。
- 系统托盘，可选。
- 开机启动，可选。
- 自动更新，最后实现。

安全要求：

- 不后台监听剪贴板。
- 只有用户点击"读取剪贴板"时才读取。
- 明确显示读取到的内容。
- 不自动向第三方应用写入文本。

---

## 11. 每个功能的完成定义

一个功能只有同时满足以下条件才算完成：

1. 功能代码完成。
2. 有输入校验。
3. 有加载状态。
4. 有失败状态。
5. 有空状态。
6. 有至少一个单元测试。
7. 涉及数据时有持久化测试。
8. 涉及 AI 时有固定 fixture 测试。
9. TypeScript 检查通过。
10. ESLint 检查通过。
11. 手动验证通过。
12. 更新相关文档。

---

## 12. 推荐开发命令

建议在 package.json 中提供：

```json
{
  "scripts": {
    "dev": "vite",
    "electron:dev": "electron .",
    "build": "tsc -b && vite build",
    "lint": "eslint .",
    "format": "prettier --write .",
    "test": "vitest run",
    "test:watch": "vitest",
    "db:generate": "drizzle-kit generate",
    "db:migrate": "drizzle-kit migrate",
    "package": "electron-builder"
  }
}
```

具体脚本名称可以根据实际 Electron 模板调整，但必须提供同等能力。
